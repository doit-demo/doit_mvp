# DOIT R0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task if native execution is selected; use superpowers:subagent-driven-development if the user selects delegation. Steps use checkbox syntax for tracking.

**Goal:** PC에서 실행하는 1:1 Execution Platform을 만들고, 이후 같은 CORE에 Cloudflare HTTPS를 연결하여 Agent와 Client의 별도 기기로 실증한다.

**Architecture:** FastAPI가 모든 권한·상태·파일·Audit의 진실 원천이다. SQLite는 SQLAlchemy 저장소와 Alembic 마이그레이션 뒤에 두고 React APP은 같은 origin의 /api를 호출한다. Electron 터미널이 역할별 세션과 CORE 및 선택적 터널의 생명주기를 관리한다.

**Tech Stack:** Python 3.13, FastAPI, SQLAlchemy, Alembic, SQLite, pytest/httpx, Pillow, Argon2, React/TypeScript, Vite, Leaflet, Electron, Playwright. Node.js 24.21.0/Python 3.13.15 설치 확인. 의존성 버전은 호환성 확인 후 lock에 고정한다. 영상 구조 검증에는 ffprobe를 사용하며 설치/경로를 실행 준비 검사에 포함한다.

**Spec:** [DOIT R0.2 설계](../specs/2026-10-07-doit-r02-design.md)

## Global Constraints

- 신규 프로젝트. 기존 소스, DB, 테스트는 없다. 제품 코드는 아직 작성하지 않았다.
- 모든 데이터 변경은 CORE /api 경유. 역할 CLIENT, AGENT, ADMIN을 서버에서 강제한다.
- Task당 Client 한 명, Agent 한 명. 재배정·입찰·결제·정산·Wallet·AI 분석은 구현하지 않는다.
- 상태: REQUESTED → ASSIGNED → ACCEPTED → IN_PROGRESS → SUBMITTED → VERIFIED → COMPLETED.
- 예외 전이: Admin의 SUBMITTED → IN_PROGRESS, 사유 필수. 모든 상태 변경은 Audit와 원자적으로 저장한다.
- 사진 JPG/JPEG/PNG/WEBP, 영상 MP4/WEBM. 원본 불변, SHA-256, 고유 서버 저장 경로.
- 한국어 UI, Agent 모바일 우선. API·DB·Storage·GEO·public origin을 환경설정으로 분리한다.
- 테스트는 임시 DB와 임시 storage 사용. 단계별 회귀 테스트 및 Git checkpoint.
- 초기 PC 내부 검증 → 동일 CORE에 Cloudflare 연결 → 기기 분리 실증. 실제 기기 실증 전 전체 완료를 주장하지 않는다.
- 삭제 명령이나 프로세스 이름만으로 다른 프로그램을 종료하지 않는다. 소유권 확인 후 DOIT 프로세스만 관리한다.

## Review Focus

1. 중복 클릭/동시 요청: 배정과 전이가 중복 Audit 또는 이중 Agent를 만들지 않아야 한다. Task 2/5 테스트.
2. 업로드 도중 연결/DB 실패: Evidence 메타데이터와 파일이 불일치하지 않고 원본이 덮어써지지 않아야 한다. Task 7 테스트.
3. 같은 PC의 세 역할 로그인: 쿠키가 섞이지 않아야 하며 URL 직접 접근에도 권한을 검사해야 한다. Task 3/11 테스트.
4. 재수행 후 Report: 과거 파일을 보존하면서 최신 회차와 검증 결과를 구분해야 한다. Task 9/10 테스트.
5. 터미널 시작 실패/강제 종료: CORE·터널이 남지 않으며 무관한 포트 소유 프로세스는 유지되어야 한다. Task 11 테스트.

## 공통 인터페이스와 파일 경계

- `core/config.py`: `Settings` — env(development/test/production), database_url, storage_root, public_origin, allowed_hosts, trusted_proxies, geo_provider, upload_max_bytes, ffprobe_path. 기본 bind는 127.0.0.1, 기본 포트 8765.
- `core/app.py`: `create_app(settings: Settings) -> FastAPI`; 요청별 DB 세션과 lifespan 종료 관리.
- `core/db.py`: `Database(settings)` — SQLAlchemy engine/session context, close(). 트랜잭션 소유자는 서비스 함수.
- `core/models.py`: User, Session, Task, Assignment, Evidence, Verification, AuditEvent. 내부 UUID와 표시용 DOIT/EV ID, UTC 시각. 역할과 상태 CHECK 제약.
- `core/auth/dependencies.py`: `current_actor(request) -> Actor`; `require_role(actor, role)`.
- `core/tasks/service.py`: `create_task(db, actor, payload) -> Task`; `visible_task(db, actor, task_id) -> Task`; `transition(db, actor, task_id, action, detail) -> Task`.
- `core/evidence/service.py`: `upload_evidence(db, actor, task_id, file, metadata) -> Evidence`; `visible_evidence(db, actor, evidence_id) -> Evidence`.
- `core/geo/service.py`: `distance_m(lat1, lng1, lat2, lng2) -> float`; `inside_geofence(..., radius_m) -> bool`.
- `core/reports/service.py`: `build_report(db, actor, task_id) -> ReportDTO`.
- `web/src/api.ts`: `api<T>(path, options) -> Promise<T>` — /api prefix, cookies, CSRF, 共通 오류. 화면에서 localStorage 기반 도메인 상태를 진실 원천으로 사용하지 않는다.
- `terminal/supervisor.cjs`: start/stop/waitHealthy, 소유 PID·생성 시각·실행 ID 관리. 종료 제어는 공개 HTTP와 분리한 로컬 파이프.
- `tests/conftest.py`: 임시 DB/storage, Client 2명·Agent 2명·Admin 1명 fixture, 역할별 세션.
- API 오류: 401 미인증, 403 역할/CSRF, 404 미존재/타인 객체, 409 상태 충돌, 413 크기, 415 파일 형식, 422 입력 오류.
