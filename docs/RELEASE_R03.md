# DOIT R0.3.0 추가 구현 기록

2026-10-08. 사용자 요청한 1~7단계를 순서대로 구현.

## 사용 흐름
1. 의뢰인: 새 의뢰 → 작성 → **임시 저장** → 다른 기기에서 같은 계정 로그인 후 새 의뢰를 열어 이어쓰기 → 제출 전 미리보기 → 확정.
2. 에이전트: 업무 시작 → **사진 촬영 / 영상 촬영 / 기존 파일 선택** → 미리보기 → 선택 취소·재촬영 또는 업로드. 25MB 상한 및 지원 확장자 안내. GPS는 사용자가 별도 기록. 파일 업로드 성공 후 선택/메모를 초기화한다.
3. 에이전트: 결과·미완료 사항을 작성하고 임시 저장 → 미리보기 → 보고서 발행. 보고서는 업무/회차별로 임시 저장되고 제출 성공 시 해당 초안을 정리한다.
4. 문서: 에이전트 일본어 / 의뢰인 한국어 번역. 완료된 번역 부분은 D1에 문서/언어별로 저장한다. 실패 후 재시도 및 재열람 시 완료 부분을 재사용한다. 전체 완료 전에는 원문을 표시하며 진행률과 오류를 안내한다. 원문과 나란히 비교할 수 있다.
5. 알림: 새 배정, 보고 제출, 재수행 요청, 의뢰인 완료를 업무 Audit와 같은 트랜잭션의 trigger로 생성한다. 로그인 화면에서 30초 간격으로 조회하며 읽음 상태는 계정에 저장한다. 최근 50개 표시. 이전 업무 이력을 새 알림으로 소급 생성하지 않는다.
6. 계정 설정: 현재 비밀번호 확인 후 새 비밀번호 설정. 모든 기존 세션을 종료한다. 관리자 화면은 본인의 현재 비밀번호로 초대·복구 코드 발행, 일반 계정 활성/비활성화를 수행한다. 초대 24시간, 재발급/복구 1시간. 코드 해시만 DB 보관, 일회 사용. 관리자 계정 변경과 진행 업무가 있는 Agent 비활성화는 제한한다. 비활성 계정 로그인/기존 세션 및 자동 배정을 차단한다.
7. 초대 수락/비밀번호 복구는 로그인 아래에서 일회용 코드와 새 비밀번호로 진행. 코드 전달은 관리자가 직접 수행한다. 이메일/문자 발송 연동은 포함하지 않는다.

## 저장과 문서
- 의뢰 초안은 사용자당 1개, 보고 초안은 업무/회차당 1개. 자동 저장이 아니라 **임시 저장 버튼**으로 저장한다.
- 작성 중 입력값과 파일은 버튼을 누르기 전에는 서버에 저장되지 않는다. 사진·영상 파일 자체는 임시 저장 대상이 아니다.
- 여러 창의 초안 덮어쓰기는 revision 조건부 저장으로 차단한다. 충돌하면 현재 내용을 보관한 뒤 다시 열도록 안내한다.
- 제출된 원문과 회차별 보고서는 불변. AI 번역을 발행 원문으로 덮어쓰지 않는다.
- 의뢰 목적/확인 항목, 요청사항 목록, 증거 요구 목록, 결과/미완료 항목을 구분한다. 인쇄 시 비교 원문은 제외하고 현재 선택 문서만 출력한다.
- 카메라 실행과 실제 코덱은 브라우저/단말별로 다르다. HEIC/MOV 변환, 영상 압축, 데스크톱 내장 녹화는 구현하지 않았다.

## 자동 백업
- Cloudflare Cron: UTC 18:00 = 한국시간 매일 오전 3시. PC 실행 불필요.
- 비공개 R2 `_backups/daily/YYYY-MM-DD/`에 DB JSON, 완성 manifest를 저장한다. 파일은 SHA-256 기반 `_backups/files/`에 중복 없이 복사한다.
- 핵심 11개 테이블을 단일 D1 batch로 조회한다. 세션·로그인 제한·복구 토큰·AI 호출 이력은 복구 대상에서 제외한다. 문서 번역 캐시는 포함한다.
- MVP 안전 한도: 테이블당 1,000행, DB JSON 20MB, 파일 복사 4분. 초과/실패 시 COMPLETE로 표시하지 않는다. 관리자 화면에서 최근 30회 결과 확인.
- 완성 manifest가 있는 백업만 복구 자료로 취급한다. 런타임 강제 종료는 RUNNING으로 남을 수 있으므로 장시간 RUNNING은 미완료로 판단한다.
- 자동 삭제/보존기간 만료 삭제는 하지 않는다. 운영 계정·버킷 전체 삭제를 견디는 외부 계정 백업은 아니다. 별도 보관과 보존 정책은 후속 운영 결정이 필요하다.
- 복원은 신규 D1에 현재 migrations를 적용한 후 database.json 데이터 적재 및 manifest 파일 매핑으로 R2 원본 경로 복구를 진행한다. 기존 운영 DB를 자동 덮어쓰는 기능은 제공하지 않는다. DB trigger와 외래 키 순서를 고려한 복구 도구 및 실제 복원 훈련은 후속 작업이다.
- 참고: [Cloudflare Cron](https://developers.cloudflare.com/workers/configuration/cron-triggers/), [R2 API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/).

## 검증 범위
타입 검사 및 번들 빌드 통과. 편집 중 문법/타입 오류 2개를 수정했다. 사용자 요청에 따라 전체 회귀, 실기기 촬영/GPS, 실제 AI 호출, 초대/복구 실제 계정 변경, 인쇄 및 복원 테스트는 실행하지 않았다. 기존 테스트의 사용자 스키마/보고 제출 조건은 후속 갱신이 필요하다.
